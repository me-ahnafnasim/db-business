# NoboSole APK Size Analysis

## Project Type
React Native Expo managed workflow (SDK 54, React Native 0.81.5)
Bundle ID: `com.nobosole.mobile`

---

## Estimated APK Size

| Build Type | Estimated Size |
|---|---|
| **Release APK (AAB/App Bundle)** | **25–40 MB** |
| **Release APK (standalone .apk)** | **35–55 MB** |
| **Debug APK** | **80–120 MB** |

These estimates account for: native binaries, JS bundle, icon fonts, Expo modules, and Google Sign-In.

---

## Factors Behind APK Size (ranked by impact)

### 1. React Native Engine (~15–25 MB) — LARGEST
The React Native JavaScript engine (Hermes), bridge, and native runtime are compiled into the APK. This is the single biggest contributor and cannot be eliminated — it's the foundation of the app.

### 2. Expo SDK Native Modules (~8–15 MB)
Expo SDK 54 bundles many native modules (expo-linear-gradient, expo-status-bar, expo-dev-client, etc.) as precompiled `.so` libraries. Even modules you only use briefly contribute their native binary weight.

### 3. Google Sign-In Native Module (~3–5 MB)
`@react-native-google-signin/google-signin` pulls in Google Play Services Auth native code and related dependencies.

### 4. JS Bundle (~1.6 MB)
Your entire app source code + Supabase SDK + i18next + all JS dependencies, compiled by Metro. Relatively small.

### 5. Icon Fonts (~4 MB, **2.7 MB wasted**)
All 19 `@expo/vector-icons` TTF files are bundled, but **only 5 are actually used**:
- **Used**: Feather (56 KB), Ionicons (384 KB), SimpleLineIcons (56 KB), AntDesign (128 KB), MaterialCommunityIcons (1.3 MB)
- **Unused (~2.7 MB)**: FontAwesome family, MaterialIcons, Fontisto, Octicons, Entypo, Foundation, Zocial, EvilIcons

### 6. No Local Images/Videos/Audio
All images are loaded from Supabase CDN at runtime — zero bundled media assets. This is good for APK size.

## Optimization Opportunities

### Quick Wins (save ~2–3 MB)
1. **Tree-shake icon fonts**: Configure `@expo/vector-icons` to only bundle the 5 font families actually imported. This alone saves ~2.7 MB.
2. **Tighten `assetBundlePatterns`**: Change from `"**/*"` to specific patterns in `app.json`.

### Medium Effort (save ~5–10 MB)
3. **Enable ProGuard/R8** in the release build to strip unused native code.
4. **Enable Hermes bytecodes** (likely already on by default in Expo SDK 54) to reduce JS bundle size.
5. **Review Expo modules**: Remove any unused Expo modules from `app.json` plugins.

### Larger Effort (save ~10+ MB)
6. **Switch to EAS Build with `apks` output** instead of `aab` if you need a smaller single APK (Android App Bundles split by architecture, making each download smaller).
7. **Use `expo prebuild` + custom native project** to selectively exclude heavy native modules.

